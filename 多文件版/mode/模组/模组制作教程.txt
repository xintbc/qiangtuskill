================================================================================
                    网页 3D 枪战 · 模组制作教程（完整版）
================================================================================

本教程教你怎么给这款 3D 枪战游戏做“模组（Mod）”。所有例子都能直接在
「多文件版」里跑（通过 mode/ 下的模组加载器自动加载）。

读完这份教程你就会做：英雄（角色）、地图、多个角色、多个地图、
给地图配套出生点（★ 新地图必做，见第 4 章末尾）、角色技能、
改玩家建模、改多个玩家建模、敌人、多人游戏下的模组、
自定义剧情章节（第 12 章）、自定义玩法模式（第 13 章：大逃杀 / 回合制），
以及怎么“注册”一个模组。
在服务器黑窗口用  mod  命令就能开关模组（不用手写清单，见下方第 0 章）；
想让模组在联机里真正生效，请看第 11 章「兼容多人模式」。


--------------------------------------------------------------------------------
★ 第 0 章 · 这套模组系统怎么用（先看这段）
--------------------------------------------------------------------------------
文件夹结构：

   多文件版/
   ├─ index.html              ← 已经自动引入了下面的加载器，你不用改它
   ├─ mode/
   │   ├─ 模组加载器.js        ← 模组加载器（自动读取清单并加载模组，别改）
   │   └─ 模组/               ← 你的模组都放这里
   │       ├─ 载入清单.js      ← 启用 / 停用模组的“开关”（改这个就行）
   │       ├─ 模组制作教程.txt  ← 就是本文件
   │       ├─ 角色_魅影.js      ← 现成的优质示例（隐身 / 瞬闪 / 假人诱饵）
   │       └─ 你的模组.js       ← 你自己写的都放这层
   （本教程每一章都给了可直接复制的完整代码，不依赖任何外部示例文件。）
   └─ js/  lib/  libs/  ...   ← 游戏本体（模组不会改这里）

启用 / 停用一个模组（两种方式，效果一样）：
   ※ 方式一（黑窗口，最省事）：启动服务器后，在黑色窗口里输入命令：
        mod            查看所有模组及启用状态（✅已启用 / ⬜未启用）
        mod on <名称>   开启某个模组      （ mod on all 开启全部）
        mod off <名称>  关闭某个模组      （ mod off all 关闭全部）
     改完刷新浏览器页面就生效，不用手动改文件。
   ※ 方式二（手写文件）：打开 mode/模组/载入清单.js，里面有个数组 window.MOD_FILES。
     数组里写着的文件名就会被加载；把它删掉就不加载。
     文件名相对于“模组/”目录，带不带 .js 都行。

   例如：'示例_角色_烈焰' 就表示加载  mode/模组/示例_角色_烈焰.js

模组文件长什么样（最小骨架）：
   (function(){
     // 在这里写你的模组代码，比如往 HEROES 里加英雄、往 MAPS 里加地图……
   })();
   用 (function(){ ... })(); 包起来是为了不让你的变量污染游戏其它地方。

加载器会自动帮你做两件事：
   1) 按清单顺序加载每个模组文件；
   2) 加载完后刷新“选英雄 / 选地图”界面，让新增内容立刻出现。

调试技巧：按 F12 打开浏览器控制台，看有没有红色报错；加载器自己也会打印
“[模组加载器] ……”的日志。

注意：本游戏对“联网对战”是服务端权威（服务器说了算）。涉及到英雄、技能、
敌人“真正在联机里生效”，往往还要改服务器（详见第 10 章）；单纯改外观、改地图、
单机加内容，只写客户端模组就够了。


--------------------------------------------------------------------------------
第 1 章 · 注册模组的教程（怎么“登记”一个模组）
--------------------------------------------------------------------------------
“注册”指的是：让你的模组被加载器认识，并在合适的时机执行你的代码。

有两种写法：

【写法 A：直接改全局数组（最简单）】
游戏把英雄、地图、敌人类型都存在几个全局变量里，你直接往里加就行：
   HEROES.push(你的英雄);
   MAPS.push(你的地图);
   ETYPES['类型名'] = 你的敌人定义;
改完界面由加载器自动刷新，不用你手动刷。

【写法 B：用 ModLoader 辅助函数（更规范、更稳）】
加载器提供了 window.ModLoader，常用接口：

   ModLoader.addHero(英雄对象)        // 加英雄
   ModLoader.addMap(地图对象)         // 加地图（地图对象带 spawns 字段会顺带注册出生点）
   ModLoader.addSpawn('地图id', 坐标表)  // ★ 给地图配出生点（第 4 章，新图必做）
   ModLoader.spawnFree(x, z)         // 自检：这个点卡不卡墙（true=空地）
   ModLoader.addStory(章节对象)       // 加一整章自定义剧情（第 12 章）
   ModLoader.addGameMode(模式对象)    // 加一种玩法模式：大逃杀 / 回合制…（第 13 章）
   ModLoader.setGameMode('id'|null)  // 启用某个玩法 / 传 null 恢复原版玩法
   ModLoader.addEnemyType('类型名', 定义对象)  // 加敌人类型
   ModLoader.setPlayerModel(函数)     // 换玩家模型（见第 6 章）
   ModLoader.spawnEnemy('类型名', x, z)  // 立刻生成一个敌人
   ModLoader.onApply(函数)            // “全部模组加载完后”要执行的代码
   ModLoader.refresh()               // 手动刷新选人 / 选图界面
   ModLoader.register({name:'xxx', init:函数})  // 登记一个带 init 的模组

register 里的 init 函数会在“全部加载完”之后被调用，适合放一些初始化逻辑。
如果你只是 push 数据，用 addHero / addMap 就够了，init 可写可不写。

【完整示例：注册一个英雄】
   (function(){
     var 我的英雄 = { k:'myhero', name:'我做的英雄', tag:'测试', fac:'未来',
       icon:'⭐', color:0x66ccff, css:'#66ccff', passive:'说明文字',
       skills:[ {k:'dash', name:'冲', icon:'⚡', cd:11, dur:2.5, desc:'突进'},
                {k:'shield', name:'盾', icon:'🛡', cd:18, dur:7, desc:'护盾'},
                {k:'eye', name:'眼', icon:'👁', cd:24, dur:6, desc:'透视'} ] };
     if (window.ModLoader) ModLoader.addHero(我的英雄);
     else if (window.HEROES) HEROES.push(我的英雄);
   })();

第 2 章 · 制作角色的模组教程（英雄）
--------------------------------------------------------------------------------
英雄就是 HEROES 数组里的一项。结构如下：

   {
     k:'唯一英文标识',          // 比如 'blaze'，别和已有英雄重复
     name:'显示名字',           // 中文随便起
     tag:'定位',                // 比如 突击 / 控场 / 医疗
     fac:'未来' 或 '暗月' 或 '' ,// 阵营；留空会显示成“本季核心”
     facDesc:'阵营描述',        // 选人界面下方的小字
     icon:'🔥',                // 头像 emoji
     color:0xff6a2a,           // 模型主色（十六进制数字）
     css:'#ff6a2a',            // 界面主题色（带 # 的字符串）
     passive:'被动技能说明文字',
     skills:[ 技能1, 技能2, 技能3 ]   // 必须正好 3 个，对应电脑端 V / B / N
   }

每个技能的格式：
   { k:'技能效果标识', name:'技能名', icon:'⚡', cd:冷却秒数, dur:持续秒数, desc:'说明' }

⚠️ 关键：技能的“效果”由 k 决定。你可以直接复用游戏里已有的技能效果，
   这样就不用改游戏代码也能让新英雄有完整技能。可用的 k 一览：

   投掷类（拿在手里→瞄准→松手抛出）：
     mine 战术探测器 / flash 闪光弹 / frag 破片手雷 / smoke 烟雾弹 /
     medsmoke 治疗烟雾 / pulse 医疗脉冲 / medkit 急救箱 /
     solar 蚀日 / orb 闪电光球 / trap 电荷陷阱 / suneye 日之眼 /
     ssmoke 暗影烟雾 / sbomb 暗影炸弹
   非投掷类（按下立即生效）：
     dash 战术突进 / rush 冲锋号令 / smash 震击 / shield 护盾投放 /
     reflect 反弹 / fortify 堡垒阵地 / eye 全域透视 / ball 球形闪电 /
     portal 日蚀之门 / sshadow 遁入暗影 / adren 肾上腺素

★ 完整可复制示例（见附带文件 示例_角色_烈焰.js）：
   (function(){
     var 烈焰 = {
       k:'blaze', name:'烈焰', tag:'突击', fac:'未来', facDesc:'自创英雄',
       icon:'🔥', color:0xff6a2a, css:'#ff6a2a',
       passive:'炽热之躯：受到手雷伤害减 20%。',
       skills:[
         { k:'dash',   name:'烈焰突进', icon:'⚡', cd:11, dur:2.5, desc:'突进' },
         { k:'shield', name:'炎之护盾', icon:'🛡', cd:18, dur:7,   desc:'护盾' },
         { k:'eye',    name:'火眼金睛', icon:'👁', cd:24, dur:6,   desc:'透视' }
       ]
     };
     if (window.ModLoader) ModLoader.addHero(烈焰);
     else if (window.HEROES) HEROES.push(烈焰);
   })();

把上面的文件存成  mode/模组/我的英雄.js，再到 载入清单.js 里加一行
'我的英雄'，进游戏选人界面就会出现“烈焰”。

第 3 章 · 制作多个角色的模组教程（多个英雄）
--------------------------------------------------------------------------------
想一次加好几个英雄，就 push 好几次（或写在一个文件里）：

   (function(){
     function 造英雄(k,name,tag,icon,col,被动,s1,s2,s3){
       return { k:k, name:name, tag:tag, fac:'未来', icon:icon,
                color:col, css:'#'+col.toString(16), passive:被动, skills:[s1,s2,s3] };
     }
     var 甲 = 造英雄('h1','霜语','控场','❄',0x66ccff,'冰冻被动',
       {k:'shield',name:'冰盾',icon:'🛡',cd:18,dur:7,desc:''},
       {k:'eye',   name:'冰眼',icon:'👁',cd:24,dur:6,desc:''},
       {k:'dash',  name:'滑冲',icon:'⚡',cd:11,dur:2.5,desc:''});
     var 乙 = 造英雄('h2','炎刃','突击','🔥',0xff6a2a,'燃烧被动',
       {k:'dash',  name:'炎冲',icon:'⚡',cd:11,dur:2.5,desc:''},
       {k:'smash', name:'炎斩',icon:'🗡',cd:14,dur:0,desc:''},
       {k:'rush',  name:'炎吼',icon:'🔥',cd:15,dur:6,desc:''});
     if (window.ModLoader){ ModLoader.addHero(甲); ModLoader.addHero(乙); }
     else { HEROES.push(甲); HEROES.push(乙); }
   })();

提示：每个英雄的 k 必须互不相同；英雄下标会自动排在现有英雄后面（不影响其它英雄）。

第 4 章 · 制作地图的模组教程（地图）
--------------------------------------------------------------------------------
地图是 MAPS 数组里的一项，核心是 build 函数（这张图怎么搭）。

   {
     id:'唯一英文id',          // 比如 'icefort'
     name:'显示名',
     icon:'🏰',
     color:'#9fe8ff',         // 选图卡片主题色
     ladder:false,            // 有没有爬梯（新图一般 false）
     tower:false,             // 有没有哨塔（新图一般 false）
     limit:90,                // 世界半径：超出这个范围会被墙挡回来
     desc:'选图界面上的说明',
     build:function(){ /* 在这里搭地图 */ }
   }

build() 被调用时，游戏已经帮你准备好三个“当前目标”：
   _mapTarget   往里 add 网格（看得见的东西：地面、墙、装饰）
   _obsTarget   往里 push 碰撞体（看不见但能挡人挡子弹的方块）
   _tpTarget    往里 push 传送点

常用建造工具（都是全局函数，直接用）：
   makeGround(组, 颜色)                      给一张图铺地面
   addBox(x,z,w,h,d,材质,kind)              实心方块：中心(x,z)、宽w、高h、深d
                                             kind 填 'border' 是边界墙（永远挡），不填=地形
   addLedge(x,z,w,h,d,材质,kind,y0)         悬空板 / 二楼：从 y0 到 y0+h，只有那层挡人、顶面可站

⚠️ 必做：每张图都要用 addBox(...,'border') 围一圈边界墙，否则玩家会跑出地图。

★ 完整可复制示例（下面这段直接整段存成 .js 就能跑）：
   (function(){
     var 冰雪要塞 = {
       id:'icefort', name:'冰雪要塞', icon:'🏰', color:'#9fe8ff',
       ladder:false, tower:false, limit:90,
       desc:'被冰封的方形要塞：四角掩体 + 中央二层小楼。',
       spawns:[[0,25],[25,0],[0,-25],[-25,0],[40,40],[-40,-40]],   // ★ 出生点（详见下面讲解）
       build:function(){
         makeGround(_mapTarget, 0xdfe9f2);                       // 地面
         var W=180,H=16,edge=86;                                // 边界墙
         addBox(0,-edge,W,H,2,null,'border');
         addBox(0, edge,W,H,2,null,'border');
         addBox(-edge,0,2,H,W,null,'border');
         addBox( edge,0,2,H,W,null,'border');
         addBox(-30,-30,8,5,8); addBox(30,-30,8,5,8);           // 四角掩体
         addBox(-30, 30,8,5,8); addBox(30, 30,8,5,8);
         addBox(0,0,4,3,4);                                     // 中央掩体
         addBox(0,0,18,6,18);                                   // 一楼主体
         for(var s=1;s<=9;s++) addLedge(-9+s*0.8,0,3,0.5,6,null,'ledge',s*0.6); // 楼梯
         addLedge(0,0,20,1,20,null,'ledge',6.2);                // 二楼楼板
         addLedge(0,9.6,4,1.2,4,null,'ledge',6.4);              // 二楼护栏
         if(_tpTarget) _tpTarget.push({x:-40,z:-40,r:2.2,to:[40,40],toName:'东南角',name:'冰窖门'});
       }
     };
     if (window.ModLoader) ModLoader.addMap(冰雪要塞);
     else if (window.MAPS) MAPS.push(冰雪要塞);
   })();

存成  mode/模组/我的地图.js，在 载入清单.js 加上 '我的地图' 即可在选图界面看到。


★★★ 必做：给地图配套出生点（新手最容易漏的一步）★★★
--------------------------------------------------------------------------------
【为什么必须做】
    开局时游戏会从「当前这张图的出生点表」里随机抽一个点把玩家放下去，逻辑是：

        MAP_SPAWNS[当前地图id]  ||  [[0, 15]]      ← 找不着就退回经典图的默认点

    你的新地图只要在 MAP_SPAWNS 里没有对应条目，就会被放到 [0,15]。
    那个坐标在你的图上很可能正好是墙体里、坑里、甚至早就跑到地图外面，
    表现就是：「一进图卡在方块里动不了」「卡进房子墙里」「直接掉出地图」。

【写法 1】地图对象里直接带 spawns（推荐，最省事）
    addMap 一旦发现地图带了 spawns，会自动帮你注册：

      var 我的地图 = {
        id:'icefort', name:'冰雪要塞', icon:'🏰', color:'#9fe8ff',
        ladder:false, tower:false, limit:90,
        desc:'说明文字',
        spawns:[[0,25],[25,0],[0,-25],[-25,0],[40,40],[-40,-40]],   // ★ 就加这一行
        build:function(){ /* 搭地图 */ }
      };
      ModLoader.addMap(我的地图);

【写法 2】单独调用 addSpawn（想分开写 / 想随时补充时用）
      ModLoader.addSpawn('icefort', [[0,25],[25,0],[0,-25],[-25,0]]);  // 一次加一批
      ModLoader.addSpawn('icefort', [50,50]);                          // 也可以一次加一个
      ModLoader.addSpawn('icefort', [[0,25]], true);                   // true = 清空重来

    不用加载器的话直接改全局也一样生效：
      MAP_SPAWNS['icefort'] = [[0,25],[25,0]];

【坐标怎么挑 —— 很重要】
   · 挑**开阔平地**放，别压在边界墙、掩体、箱子、树、楼梯、传送点上；
   · 建议一张图撒 6~12 个点，开局随机抽，不会每次都同一个地方；
   · 别紧贴边界墙 —— 玩家有 0.5 米身位，贴太近一落点就嵌进墙里；
   · 房间的图（像实验室那种）尽量放走廊 / 大厅，别塞进塞满家具的小隔间。

【出生点自检】
    进到你的图之后，在浏览器控制台敲：
        ModLoader.spawnFree(0, 25)
    返回 true ＝ 是空地；返回 false ＝ 这个点压墙了，换个坐标。

★ 万一坐标没选对也不怕：游戏自带兜底 —— 出生时若发现这个点落在墙里，
  会自动向外搜索最近的空位再落点，不会让你卡死在墙里。但最好一开始就把坐标选对。

⚠️ 联机注意：出生点分「客户端」和「服务端」两份。上面这一步只保证单机正常；
   要让你的地图在联机里也能正常出生，还得把同一份坐标加进服务端 —— 见第 11 章。

第 5 章 · 制作多个地图的模组教程（多张地图）
--------------------------------------------------------------------------------
和多个英雄同理，push 多个地图对象即可。建议每个地图 id 都不同：

   (function(){
     var 地图A = { id:'mapA', name:'沙漠', icon:'🏜', color:'#e8c98a', ladder:false, tower:false,
       limit:100, desc:'一张空旷的沙漠图。',
       spawns:[[0,40],[40,0],[0,-40],[-40,0]],          // ★ 沙漠图的出生点
       build:function(){ makeGround(_mapTarget,0xdcc79a);
         addBox(0,-92,200,16,2,null,'border'); addBox(0,92,200,16,2,null,'border');
         addBox(-92,0,2,16,200,null,'border'); addBox(92,0,2,16,200,null,'border');
         addBox(-20,-20,10,6,10); addBox(20,20,10,6,10); } };
     var 地图B = { id:'mapB', name:'丛林', icon:'🌲', color:'#6abf69', ladder:false, tower:false,
       limit:100, desc:'一张长满掩体的丛林图。',
       spawns:[[0,50],[50,0],[0,-50],[-50,0]],          // ★ 丛林图的出生点（两张图各自独立）
       build:function(){ makeGround(_mapTarget,0x4f7a3a);
         addBox(0,-92,200,16,2,null,'border'); addBox(0,92,200,16,2,null,'border');
         addBox(-92,0,2,16,200,null,'border'); addBox(92,0,2,16,200,null,'border');
         addBox(-15,15,8,7,8); addBox(15,-15,8,7,8); addBox(0,0,6,9,6); } };
     if (window.ModLoader){ ModLoader.addMap(地图A); ModLoader.addMap(地图B); }
     else { MAPS.push(地图A); MAPS.push(地图B); }
   })();

   ★ 每张图都要各自配一份 spawns —— 地图 id 不同，出生点表也是彼此分开的。
     漏配哪一张图，进那张图时人就会被放到经典图的默认点 [0,15] 上，
     于是表现为「卡在墙里 / 掉出地图」。详细讲法见第 4 章末尾那一节。


--------------------------------------------------------------------------------
第 6 章 · 角色技能的模组教程（英雄技能）
--------------------------------------------------------------------------------
技能效果由 HEROES 里 skills[].k 决定（详见第 2 章的“可用 k 一览”）。
也就是说：你新英雄的技能，直接复用已有 k 就能用，无需改代码。

做技能有两种方式：

【方式一 · 复用现成效果（最简单）】
   技能 k 用第 2 章“可用 k 一览”里的现成值（dash/shield/eye/portal/ball…），
   游戏本来就认识它们，无需写任何逻辑。适合“只是想组个新英雄”的情况。

【方式二 · 真正自定义技能（推荐做自己的技能）★新增】
   不想套原版效果？用 ModLoader.addSkill(k, fn) 把你的技能效果注册进 CUSTOM_SKILLS，
   游戏 heroCast 遇到这个 k 会直接把控制权交给你的 fn —— 不用改 js/41 源码！

     ModLoader.addSkill('我的技能', function(i, s, H){
       // i=技能槽位(0/1/2)  s=技能对象(含 name/cd/dur…)  H=英雄对象
       // 在这里写你自己的效果，能用的“游戏积木”见下
       return true;          // 返回 true/undefined = 已被模组处理；返回 false = 交给原版分支
     });

   自定义技能里能直接调用的全局积木：
     camera            玩家相机；camera.position.x / .z 是世界坐标
     yaw               当前朝向（弧度）；Math.sin(yaw)/Math.cos(yaw) 求前方向量
     SK / S            玩家状态（SK.dash 突进、SK.shield 护盾、SK.cds[i] 各技能冷却…）
     enemies[]         场上所有敌人；世界坐标在 e.root.position（不是 e.g！）
     e.hp / e.maxHp    敌人血量；e.flash=0.3 让敌人闪白；e.hb 是它的血条
     spawnParticle(位置, 颜色, 数量)   撒火星/火花
     killEnemy(e, 下标, false)         击杀（下标用你 for 循环里的那个 n）
     heroFX*(...)      各种技能特效（heroFXTrail / heroFXShield / heroFxRingAt(x,z,色,r0,r1,life) …）
   完整可复制示例见附带文件 示例_角色_烈焰.js：三个技能（烈焰突进 / 炎之护盾 / 火焰新星）
   全部是自定义效果，没有任何一个调用原版 dash/shield/eye。

技能对象各字段含义：
   k      效果标识。方式一用现成值；方式二用你自定义的字符串（别和现成 k 撞名）
   name   显示名
   icon   图标 emoji
   cd     冷却秒数（本地 HUD 用；联机时服务器有更严格的权威冷却）
   dur    持续秒数（护盾/透视/突进余势等用；瞬发技能填 0 即可）
   desc   选人界面里的说明文字

示例（方式二：给英雄“烈焰”配三个“自己写的”技能）：
   skills:[
     { k:'blaze_dash',   name:'烈焰突进', icon:'⚡', cd:9,  dur:2.5, desc:'突进并在落点点燃敌人' },
     { k:'blaze_shield', name:'炎之护盾', icon:'🛡', cd:16, dur:7,   desc:'护盾+灼烧贴脸敌人' },
     { k:'blaze_nova',   name:'火焰新星', icon:'☄', cd:20, dur:0,   desc:'以自身炸开火环重创周围' }
   ]
   // 然后分别 ModLoader.addSkill('blaze_dash', …) / addSkill('blaze_shield', …) / addSkill('blaze_nova', …)
   // 把每个 k 的效果函数注册进去（详见 示例_角色_烈焰.js）。

⚠️ 联机提醒：英雄技能在联机里由服务器结算与校验。新英雄若用“现有 k”，
   只要服务器本来就认识那个 k（dash/shield/eye 都认识），联机就能正常放。
   如果你新加了 k（改了 heroCast），就必须同时在服务器登记，否则联机会被拦截。

第 7 章 · 更改玩家建模的模组教程
--------------------------------------------------------------------------------
“玩家建模”指的是“别人看到的你 / 你看到的别人”的 3D 身体模型
（第一人称看不到自己身体；联机时最直观——所有人的身体都会变成你改的样子）。

做法：覆盖全局函数 _buildPlayerModel，让它返回一个“被改造过”的模型对象。

★ 最安全的写法（新手必用）：先调原版建好完整模型，再改色 / 换部件。
   这样动画需要的字段一定齐全，不会让联机动作崩掉。
   （见附带文件 示例_玩家建模_黄金战士.js）：
   (function(){
     var _orig = window._buildPlayerModel;
     if (typeof _orig !== 'function') return;
     window._buildPlayerModel = function(){
       var m = _orig();                       // 原版完整模型
       if (m && m.root && m.root.traverse){
         m.root.traverse(function(o){
           if (o.isMesh && o.material && o.material.color){
             o.material = o.material.clone();
             o.material.color.setHex(0xffd24a);   // 改成金色
           }
         });
       }
       return m;
     };
   })();

模型对象必须包含的字段（动画会读这些，缺了联机会报错）：
   root / yawPivot / modelGroup / head / hb / hbMat /
   legL / legR / bodyPivot / armRig / lArm / rArm /
   leftLeg / rightLeg / gun / knifeRig / nadeRig
（用“先调原版再改”的写法，这些字段原版都已经帮你建好了，你只动外观即可。）

想“彻底换一个造型”？难点在于上面这些字段你都得自己建出来。
除非你很熟悉 three.js，否则强烈建议用上面的“改原版”方式，只换颜色 / 换某个部件网格。
比如只换头：在 m.root 里找到 head 那块网格，替换成自己的几何体即可。

第 8 章 · 更改多个玩家建模的模组教程（不同玩家不同造型）
--------------------------------------------------------------------------------
有时候你想“按英雄 / 按名字”给不同玩家不同造型。做法：在覆盖后的
_buildPlayerModel 里，根据传入的信息做分支。

注意：原版 _buildPlayerModel() 本身不带“这是谁”的参数，但联机时每个玩家
在创建模型后，游戏会把它的英雄 / 名字等信息挂到玩家对象上。最稳妥的做法是：
先用原版建模型，再根据“这个玩家当前用的英雄”来改色。

示例：根据英雄换主色（下面的 heroKey 要结合你的游戏规则去取，这里给思路）：
   (function(){
     var _orig = window._buildPlayerModel;
     if (typeof _orig !== 'function') return;
     var 配色 = { scout:0x49b6ff, rusher:0xff8a3d, guard:0x5ef07a, medic:0xffd75e,
                  eclipse:0xb07dff, lightning:0x6ff0ff, yingyue:0x8f7bff };
     window._buildPlayerModel = function(){
       var m = _orig();
       // 这里可以读取“当前这个玩家用的英雄”来决定颜色；
       // 具体取值点取决于联机数据挂载位置，常见做法是改完模型后由外部再上色。
       // 作为示例，这里把所有玩家都按“阵营/英雄”思路统一染成蓝色系：
       if (m && m.root && m.root.traverse){
         m.root.traverse(function(o){
           if (o.isMesh && o.material && o.material.color){
             o.material = o.material.clone();
             o.material.color.setHex(0x49b6ff);
           }
         });
       }
       return m;
     };
   })();

更精细的“每人不同”：可以在 onApply 之后，监听玩家加入事件，对每个人的
model 单独上色（需要你熟悉 30_联机.js 里的 NET.players 结构）。教程建议先掌握
“统一改色”，再进阶到“每人不同”。

第 9 章 · 敌人的模组教程
--------------------------------------------------------------------------------
敌人类型存在全局对象 ETYPES 里。加一种新敌人 = 往 ETYPES 加一项。

字段含义：
   c        颜色（建模主色，十六进制）
   hp       血量
   spd      移动速度（0.02 很慢，0.11 很快）
   sz       体型（1=普通，1.4=重甲，1.6=更大）
   sc       击杀得分
   dmg      碰到你造成的伤害
   gold     击杀掉落金币
   canShoot 是否会射击（true=远程兵建枪；false=近战兵建刀）
   远程兵还可选：shootRange / minRange / shootCD / bulletSpd / bulletCount / spread / aimTime / aimColor

★ 完整可复制示例（见附带文件 示例_敌人_石巨人.js）：
   (function(){
     if (window.ETYPES){
       ETYPES.stone = { c:0x9a8c7a, hp:120, spd:0.025, sz:1.6, sc:400, dmg:14, gold:60, canShoot:false };
     }
   })();

加完类型后，它默认不会自动出现（波次只刷 basic/fast/tank/elite）。
让它在波次里出现，两种方法：
   ① 手动生成：按 F12，控制台输入  ModLoader.spawnEnemy('stone', 0, 10)
   ② 包裹 nextWave（让第 3 波起每波多刷一只）：
      if (window.ModLoader){
        ModLoader.onApply(function(){
          if (typeof nextWave === 'function'){
            var _ow = nextWave;
            nextWave = function(){
              var r = _ow.apply(this, arguments);          // 先跑原版
              try{ if (typeof createEnemy==='function' && window.S && S.wave>=3) createEnemy('stone'); }
              catch(e){}
              return r;
            };
          }
        });
      }
（示例文件 示例_敌人_石巨人.js 里这段是注释掉的，取消注释就能启用。）

第 10 章 · 应用在多人游戏下的模组教程（联机要注意什么）
--------------------------------------------------------------------------------
本游戏联机是“服务器权威”：客户端把操作发上去，服务器结算伤害、位置、技能，
再把结果广播给所有人。所以模组能不能在联机里生效，分情况：

【在联机里“直接生效”的模组（纯客户端）】
   · 改玩家建模（第 7/8 章）：你换的只是“别人看你 / 你看别人”的显示模型，本地就能改。
   · 改地图（第 4/5 章）：地图在客户端构建，你自己选这张图进，就能玩你加的图
     （前提是服务器也允许这张图被选中；若服务器按固定 MAPS 校验，需同步加）。
   · 改界面 / 改颜色等外观类。

【在联机里“需要改服务器”的模组】
   · 新增英雄：服务器用 SKILL_IDS / SKILL_CD 校验英雄与技能冷却。
     你新加的英雄 k 若不在服务器 SKILL_IDS 里，联机放技能会被服务器拦截。
     解决：在 服务器/服务端.js 里，把你的英雄 k 加进 SKILL_IDS，
     并把三个技能冷却写进 SKILL_CD。
   · 新增技能效果（自己新写的 k）：客户端现在不用改 heroCast 了——用 ModLoader.addSkill(k, fn) 注册即可（见第 6 章）；
     服务器也要能识别这条技能报文并结算，否则联机放出来“没效果 / 被踢”。
   · 新增敌人类型：敌人由服务器生成与驱动（联机里服务端不生成 AI，但类型校验 /
     波次若在服务端，需要同步）。单机加敌人类型即可；若要联机波次里有，也要改服务器。

简明结论：
   · 想自己单机爽、或只改外观 / 地图显示 → 只写客户端模组（本教程前 9 章）就够。
   · 想让“新英雄 / 新技能 / 新敌人在联机里真正能打” → 除了客户端模组，
     还要动 服务器/服务端.js（英雄表、技能冷却表、敌人类型表），并重跑
     工具/生成多文件服务端.py 把改动同步到 多文件版/服务端.js。

安全提醒：联机模组请只用于你和朋友自建的房间，不要用于破坏他人游戏的平衡。


================================================================================
第 11 章 · 让模组兼容多人模式（联机生效的真相与做法）
--------------------------------------------------------------------------------
很多作者做到第 10 章会卡住：“我 mod on 开了，单机也好好的，为什么一联机就没用？”
这一章专门讲“兼容多人模式”到底要做什么、哪些能直接兼容、哪些必须改服务器。

【先弄清联机的“权威边界”】
  · 联机房间里【没有 AI 敌人】（服务器不生成），玩家与玩家互为敌人。
    所以“自定义技能打敌人”“新增敌人类型”这类 PVE 内容，在纯联机对战里【没有目标】，
    主要在单人 / 剧情 / 你自己的训练房里用得着。
  · 玩家之间的伤害、位置、技能冷却，由【服务器】结算并广播。
    客户端模组（加载器注册的英雄 / 技能 / 地图 / 建模）只在“客户端侧”生效，
    除非服务器也认识它们，否则联机里别人看不到、也吃不到你的效果。

【各类模组的联机兼容性清单】
  1) 玩家建模（第 7/8 章）—— ✅ 天然兼容，不用改服务器
     模型是客户端渲染：你改的是“你自己的模型”，对方客户端渲染“对方看到的你”。
     双方都启用同款建模模组 → 外观一致；只有你启用 → 对方看到原版（不影响战斗）。

  2) 地图（第 4/5 章）—— ⚠️ 部分兼容
     客户端能 build 这张图；但联机房间的可用地图由【房主 / 服务器】的 MAPS 决定。
     若服务器 MAPS 里没有你的图，房主选不到 → 进不去。
     做法：把地图定义也加进 服务器/服务端.js 的 MAPS（或让服务器读取 mode/地图），
     再重跑 工具/生成多文件服务端.py 同步。

     ★★ 别忘了：出生点也要同步一份到服务器（最容易漏的一步）★★
        联机的出生点是【服务器】下发的，服务器自己有一份独立的 MAP_SPAWNS
        （见 服务器/服务端.js 第 840 行附近），它按图取点：

            const table = MAP_SPAWNS[地图id] || SAFE_SPAWNS;   // 找不着就退回经典图的点

        所以：哪怕你在客户端已经用 addSpawn / spawns 配好了出生点，
        只要**服务器那份表里没有你的图**，联机时人还是会被塞到经典图的默认点，
        于是又变成「进图卡在墙里」「掉出地图」 —— 单机正常、联机却出毛病，
        十有八九就是这里没同步。

        做法：在 服务器/服务端.js 的 MAP_SPAWNS 里加一条，坐标必须和客户端**逐点一致**：

            const MAP_SPAWNS = {
              classic: [...],
              eclipse: [...],
              lab:     [...],
              icefort: [[0,25],[25,0],[0,-25],[-25,0],[40,40],[-40,-40]]   // ← 加你的图
            };

        ⚠️ 别在这个对象字面量里插注释 —— 会把那份数据解析坏（以前踩过这坑）。
        改完同样要重跑 工具/生成多文件服务端.py 同步到 多文件版/服务端.js，再重启服务器。
        记住项目铁律：服务端有「服务器/服务端.js（权威源）」和「多文件版/服务端.js」两份，
        只改权威源 + 重跑生成脚本，否则改动会在下次生成时被覆盖掉。

  3) 英雄（第 2/3 章）+ 自定义技能（第 6 章）—— ⚠️ 需改服务器才能联机选 / 放
     · 联机选英雄时，服务器只认 SKILL_IDS 里的英雄 k
       （见 服务器/服务端.js 第 334 行：const SKILL_IDS = ['scout','rusher',...]）。
       你的自定义英雄 k（如 blaze / phantom）不在里面 → 联机选了会被服务器直接忽略
       （代码见第 1242 行：if (SKILL_IDS.indexOf(k) < 0) return;）。
     · 接入步骤：
       ① 在 服务器/服务端.js 把你的英雄 k 加进 SKILL_IDS 数组；
       ② 在 SKILL_CD（第 336 行）里补上该英雄的三个技能冷却；
       ③ 改完重跑 工具/生成多文件服务端.py 同步到 多文件版/服务端.js，重启服务器。
     · 自定义技能效果：客户端 heroCast 里的 CUSTOM_SKILLS 钩子已经接好（单机 / 剧情完整可用）。
       但联机里“对玩家造成伤害”要走上游戏的“命中上报”原生链路——否则只有你本地看得到特效、
       别人不受伤。最省事的做法见下方“进阶”。

  4) 敌人（第 9 章）—— ⚠️ 仅单机 / 剧情
     联机不生成 AI 敌人（服务器不生成），所以敌人类型主要在单人 / 剧情里用；
     想让联机波次里有，需要服务器也生成敌人（当前版本联机无此机制，属进阶改造）。

【当前版本已经帮你做好的客户端能力（你不用再写）】
  · 自定义技能钩子 CUSTOM_SKILLS：heroCast 里已接好，单机 / 剧情下自定义技能完整可用；
  · 模组加载器 + 黑窗口 mod 开关：随时启用 / 停用模组、刷新浏览器即生效。

【进阶：让自定义技能在联机里真正“打人”的两条路】
  · 思路 A（推荐，最稳，不用改服务器）：
    你的英雄三个技能都【用原版已有的 k】（dash / shield / eye / pulse / medkit …），
    这些 k 在联机里本来就走原生同步（服务器结算冷却、效果走原生链路）。
    你要的“不同表现”，用 ModLoader.onApply 包裹相关函数做【视觉 / 数值微调】即可。
    这样不用碰服务器，联机立刻能用。
  · 思路 B（完全自定义 k，改动较大）：
    需要在 服务器/服务端.js 里新增“技能报文解析”——收到你的技能 k 时，
    服务器执行对应的范围伤害 / 状态，并广播给所有玩家。这要熟悉 WebSocket 报文结构，
    建议先把 A 跑通、熟悉机制后再做。

【一句话总结】
  · 自己单机爽、改外观、加地图显示 → 只写客户端模组就够，用黑窗口 mod 开关管理；
  · 想让“新英雄 / 新技能在联机里被所有人看到并生效” →
    英雄 k 必须进服务器 SKILL_IDS（+SKILL_CD），
    自定义技能效果要么借壳原版 k（思路 A），要么在服务器加报文结算（思路 B）；
    改完重跑 工具/生成多文件服务端.py，重启服务器即可。

第 12 章 · 自定义剧情章节（自己写一章剧情）
--------------------------------------------------------------------------------
游戏自带两章（第一章「打通救援线」、第二章「救出蚀日者」）。
用 ModLoader.addStory(章节对象) 就能再加一章，而且这一章的内容完全由你定：
用哪张地图、从哪出生、开场白说什么、HUD 显示什么目标、每帧怎么推进、赢了给什么奖励。

【最小可用：只换地图和台词，玩法沿用原版「清剿 → boss → 决斗」】
   ModLoader.addStory({
     n:3, icon:'🌋', name:'第三章 · 火山据点', map:'火山据点',
     desc:'暗月把最后一批实验体转移到了火山口据点 —— 端掉它。',
     mapId:'volcano',          // 用你自己的地图（第 4 章做的那张）
     spawn:[0,25],             // 固定出生点；不写就从该图出生点表随机抽
     need:30,                  // 干掉 30 个才进 boss（默认 24）
     lines:['火山口的空气烫得呛人。','暗月把最后一批实验体藏在了这里。','清干净，然后回家。']
   });

【全部可选字段】
   n                    章节号（必填；别和原版的 1 / 2 撞车）
   icon / name / map / desc    章节选择界面上的显示（map 只是显示的地图名文字）
   mapId:'地图id'       真正用哪张地图；不填用剧情默认图
   spawn:[x,z]          固定出生点
   need:数字            清剿目标数（沿用原版流程时生效）
   lines:[...]          开场台词（数组，一句一条）
   init:function(){}    刚进图时执行（放道具、设变量）
   begin:function(){}   开场白演完后、玩法正式开始时（替代原版"开始清剿"）
   tick:function(dt){}  每帧推进；return true = 你已全权接管，原版流程不再跑
   goal:function(){}    HUD 上显示的目标文字（返回字符串）
   winLines / loseLines 结局台词
   reward:function(win){}   通关奖励（比如解锁某个英雄）
   done:function(){}    章节列表里显示"已通关"吗（返回 true / false）

【想自己写玩法：用 tick 接管（例：限时死守 3 分钟）】
   ModLoader.addStory({
     n:3, icon:'⏱', name:'第三章 · 限时死守', map:'日蚀环城',
     mapId:'eclipse', spawn:[0,0],
     lines:['守住这片街区，撑过 3 分钟。'],
     begin:function(){ STORY_.phase='hunt'; },      // 借用原版 hunt 阶段（会正常刷兵）
     goal:function(){ return '死守 · 剩余 '+Math.ceil(180-(STORY_.survT||0))+' 秒'; },
     tick:function(dt){
       STORY_.survT=(STORY_.survT||0)+dt;
       if(STORY_.survT>=180){ storyEnd('win'); return true; }   // 撑满 3 分钟算赢
       return false;                      // 返回 false = 原版 hunt 逻辑照常跑
     },
     winLines:['增援到了。'], loseLines:['街区失守了……'],
     reward:function(win){ if(win) showMsg('🎉 通关奖励','#fc0'); }
   });

   小提示：tick 返回 false（或不写返回值）＝还能享受原版的刷兵 / boss / 决斗流程；
           返回 true ＝这一帧你全包了，原版流程不再参与。

第 13 章 · 自定义玩法模式（做成瓦罗兰特 / 和平精英那样）
--------------------------------------------------------------------------------
原版玩法是"一波一波刷怪"。想换成完全不同的规则（回合制战术射击、缩圈大逃杀…），
就用玩法模式钩子：注册一个模式 → 启用 → 之后开局都按你的规则来。

【可用的钩子点，想用哪个用哪个】
   start:function(){}      开局（给了它，就不再走原版"第一波刷怪"）
   tick:function(dt){}     每帧推进（dt = 本帧秒数）
   hud:function(){}        HUD 那一栏显示什么（返回字符串）
   onDeath:function(){}    玩家阵亡时；return true = 不走原版"游戏结束"面板
   end:function(win){}     自己宣布结束

【例一：和平精英式 · 缩圈大逃杀】
   ModLoader.addGameMode({
     id:'br', name:'大逃杀', icon:'🪂', desc:'毒圈不断收缩，活到最后的人吃鸡。',
     start:function(){
       for(var i=0;i<20;i++){                       // 撒一批敌人当"其他玩家"
         var a=i/20*6.283, r=20+Math.random()*40;
         ModLoader.spawnEnemy('basic', Math.cos(a)*r, Math.sin(a)*r);
       }
       this._r=70; this._t=0;                       // 圈的初始半径 / 已过秒数
     },
     tick:function(dt){
       this._t+=dt;
       this._r=Math.max(8, 70-this._t*1.2);         // 每秒收 1.2 米，最小 8 米
       var d=Math.sqrt(camera.position.x*camera.position.x+camera.position.z*camera.position.z);
       if(d>this._r){ S.hp-=dt*8; updateHp(); }     // 圈外每秒掉 8 血
       var alive=0; for(var i=0;i<enemies.length;i++) if(!enemies[i].isNet) alive++;
       if(this._r<=8 && alive===0) this.end(true);  // 圈缩到底 + 没人了 = 吃鸡
     },
     hud:function(){ return '🪂 大逃杀 · 剩余 '+enemies.length+' 人 · 圈 '+Math.round(this._r)+'m'; },
     onDeath:function(){ return false; },           // 死了正常弹结算（＝淘汰）
     end:function(win){ showMsg(win?'🍗 大吉大利，今晚吃鸡！':'💀 你被淘汰了', win?'#fc0':'#f44'); S.over=true; }
   });
   ModLoader.setGameMode('br');      // 启用

【例二：爆能器模式 · 多人自建房（真人对抗，服务端已实现）】
   这才是瓦罗兰特那一套：进房**自动分队（不限几 v 几）**、进攻方带包、走到点位长按 F 安放、
   守方可以拆除 —— 引爆 = 攻方得分，拆除 / 超时 / 团灭 = 守方得分。
   规则由**服务端**权威裁决（位置与伤害本来就是服务器广播的），客户端只管显示与上报操作。

   (function(){
     var 房号='我的房间';                    // ← 改这个就是你的自建房（同号的人才碰得到面）
     var S={phase:'live',round:1,score:[0,0],timer:0,fuse:0,plant:0,defuse:0,site:{x:0,z:30}};

     // ① 让每次 join 都带上 mode / room —— 这样才会进到 spike 的自建房里
     var _ns=window.netSend;
     window.netSend=function(o){
       try{ if(o&&o.t==='join'){ o.mode='spike'; o.room=房号; } }catch(e){}
       return _ns?_ns(o):undefined;
     };

     // ② 接住服务端广播的爆能器状态
     ModLoader.onApply(function(){
       var _om=window.netOnMsg;
       window.netOnMsg=function(m){
         try{
           if(m&&m.t==='spike'){
             S.phase=m.phase; S.round=m.round; S.score=m.score||[0,0];
             S.timer=m.timer; S.fuse=m.fuse; S.plant=m.plant||0; S.defuse=m.defuse||0;
             if(m.site)S.site=m.site;
             return;
           }
         }catch(e){}
         return _om?_om(m):undefined;
       };
     });

     // ③ HUD 显示 + 每帧把"我正在按 F 安放 / 拆除"报给服务端
     ModLoader.addGameMode({
       id:'spike', name:'爆能器', icon:'💣',
       hud:function(){
         if(S.phase==='planted') return '💣 已安放 · '+S.fuse+' 秒后引爆'+(S.defuse>0?(' · 拆除 '+S.defuse+'/7'):'');
         if(S.plant>0) return '💣 安放中 '+S.plant+' / 4 秒';
         return '💣 第 '+S.round+' 回合 · '+S.timer+' 秒 · 攻 '+S.score[0]+':'+S.score[1]+' 守';
       },
       tick:function(){
         if(typeof NET==='undefined'||!NET.connected)return;
         var dx=camera.position.x-S.site.x, dz=camera.position.z-S.site.z;
         var 在点位=(dx*dx+dz*dz<=16);                  // 点位半径 4 米
         var 动作=(在点位&&!!keys.KeyF)?(S.phase==='planted'?'defuse':'plant'):'';
         netSend({t:'spike', a:动作, on:动作?1:0});
       }
     });
     ModLoader.setGameMode('spike');
   })();

   服务端已经做好的（不用你写）：自动分队、回合计时、安放 / 拆除进度、引信倒计时、
   比分与团灭判定、每回合结束 5 秒后开下一回合。
   想改数值就改 服务器/服务端.js 里的这几个常量，再重跑 工具/生成多文件服务端.py：
     SPIKE_ROUND_TIME=100  每回合秒数
     SPIKE_PLANT_TIME=4    安放所需长按秒数
     SPIKE_DEFUSE_TIME=7   拆除所需长按秒数
     SPIKE_FUSE=40         安放后引信秒数
     SPIKE_SITE_R=4        点位半径（米）

【常用开关与积木】
   ModLoader.setGameMode('id')        启用某个模式
   ModLoader.setGameMode(null)        关掉，恢复原版玩法
   ModLoader.listGameModes()          看看已注册了哪些模式
   ModLoader.spawnEnemy('类型',x,z)   刷敌人（basic / fast / tank / elite）
   camera.position.x / .z             玩家坐标（算圈内圈外、算距离都靠它）
   S.hp / S.maxHp                     血量；改完记得 updateHp()

   showMsg('文字','颜色')              屏幕中间弹一条提示

⚠️ 联机注意：玩法模式默认是**纯客户端**的 —— 联机时位置与伤害都由服务器广播，
   你这套规则只对自己这台机器生效。想让联机也按你的规则玩，必须同时改服务器
   （思路见第 11 章）。

【自建房 / 多人模式：房间是怎么隔离的（batch166 已改好服务端）】
   服务端现在用「房间钥匙」决定谁能看见谁：

       房间钥匙 = 有玩法模式  ?  "模式:房号"  :  "地图id"

     · 没带 mode  → 房间 = 地图（和以前完全一样，向后兼容）
     · 带了 mode  → 房间 = 模式:房号 —— 同一模式、同一房号的人才互相见面

   于是三种隔离同时成立：
     · 玩**不同模式**的人      → 房间钥匙不同 → 绝不会碰面
     · 同模式但**房号不同**    → 不同自建房   → 互不可见
     · 房号留空               → 该模式的公共房；填了 → 你自己的自建房，只有同号的人进得来

   客户端接入：join 报文多带两个字段就行
       netSend({ t:'join', n:'名字', cid:'本机ID', map:'eclipse',
                 mode:'spike', room:'我的房间' });
       · mode  玩法模式 id（字母数字，别带冒号）
       · room  自建房号（留空 = 该模式的公共房）
   服务端回 welcome 时会把 mode / room 原样发回来，界面上就能显示"当前房间"。

   服务端实现要点（已改好，方便你二次开发）：
     · roomKeyOf(p)  房间钥匙；mapIdOf(p)  地图 id（出生点 / 换图判断用它）
     · mapOf(p) 现在是 roomKeyOf 的别名 —— 全部 52 处广播过滤因此自动按房间隔离
     · 人数上限按房间钥匙统计（每间 15 人），总闸放宽到 16 间房
     · 重连 / 换图都会带上 mode、room，不会串房

                              常见问题（FAQ）

Q1：我加了英雄，但选人界面没出现？
A：① 检查 载入清单.js 里有没有写这个文件名；② 按 F12 看控制台有没有报错；
   ③ 确认你的 HEROES.push / ModLoader.addHero 写对了（k、skills 三项齐全）。

Q2：地图能选，但进去是空的 / 人能走出去？
A：build() 里忘了围边界墙。用 addBox(...,'border') 把四边围起来；并且 limit
   要和墙的位置匹配（limit 是活动半径，墙要挡在 limit 附近）。

Q3：一进图就卡在方块里 / 卡进房子墙里 / 直接掉出地图？★ 新地图最常见
A：这是「出生点没配」的典型症状。游戏开局从当前地图的出生点表随机取点，
   找不到就会退回经典图的默认点 [0,15] —— 那个点在你的图上多半是墙里或地图外。
   ① 客户端：给地图对象加 spawns 字段，或写 ModLoader.addSpawn('你的id',[[x,z],...])
      （详见第 4 章末尾那一节）；
   ② 联机：还要把**同一份坐标**加进 服务器/服务端.js 的 MAP_SPAWNS，再重跑
      工具/生成多文件服务端.py（详见第 11 章）—— 否则单机正常、联机照样卡墙；
   ③ 选点技巧：挑开阔平地、别贴边界墙（玩家有 0.5 米身位）、多撒几个点；
   ④ 自检：进图后在控制台敲 ModLoader.spawnFree(x,z)，返回 true 才是空地。

Q4：新英雄技能放不出来？
A：单机先看技能 k 是不是第 2 章列表里的；联机还要服务器认识这个 k（第 10 章）。

Q5：改玩家建模后联机动作卡住 / 报错？
A：一定是模型对象缺字段了。请务必用“先调原版再改色”的写法（第 7 章），
   不要从零手写整个模型，除非你补齐了第 7 章列出的所有字段。

Q6：怎么备份 / 删除模组？
A：删掉 mode/模组/ 里对应的 .js，并从 载入清单.js 移除那一行即可；
   不想要整个系统，把 载入清单.js 数组清空就行，游戏恢复原本样子。
