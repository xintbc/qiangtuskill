## 1. 模组是什么 · 怎么启用

**模组 = 一个普通 .js 文件**，放在 `多文件版/mode/模组/` 目录里，游戏会自动加载。

启用 / 停用只改一个文件——`多文件版/mode/模组/载入清单.js`：

```js
window.MOD_FILES = [
  '角色_魅影',
  '角色_暗影',
  '角色_夜莺',
  '示例_枪械包',
  // '角色_我的新英雄',     // ← 想启用就取消注释；想停用就注释掉或删掉这行
];
```

规则：
- 写**文件名（不含 .js）**，按数组顺序加载；
- 文件名用中文没问题（浏览器和游戏服务器都支持）；
- 改完**刷新页面**即可生效，不需要重启服务器（模组是纯客户端文件）；
- 想让模组在**服务器黑窗口自检**里也被识别（会打印启用了哪些模组），改完清单后重跑一次 `工具/生成多文件服务端.py`。

**三层文件的关系（很重要）**：

| 文件 | 作用 | 改完要做什么 |
|------|------|--------------|
| `多文件版/mode/模组/你的模组.js` | 模组本体（**手维护的活源**） | 刷新页面即可 |
| `网页3D枪战游戏.html` | 客户端**唯一权威源** | 重跑 `工具/拆分.py` 生成多文件版 |
| `服务器/服务端.js` | 服务端**唯一权威源** | 重跑 `工具/生成多文件服务端.py` |

> 引擎改动（比如新增一种网络消息）必须落到权威源，再重建；模组文件是独立的，重建不会覆盖它。

## 2. 模组管理面板（装 / 启停 / 删 / 服务器自动同步）【batch225】

不想改代码的玩家也能管模组：**设置 → 🧩 模组管理**（手机 / 电脑都有）。

```
┌──────────────────────────────────────┐
│              🧩 模组管理              │
│   存储位置：💻 服务器的 Mods 文件夹    │
│ ┌──────────────────────────────────┐ │
│ │ 角色_魅影.js   内置 ● 启用中      │ │
│ │ 手枪包.js      已装 ● 启用中 [关闭][删除] │
│ └──────────────────────────────────┘ │
│ [📂 安装模组（选文件）] [🌐 从服务器同步] │
│ [↺ 恢复内置模组]      [关闭]          │
└──────────────────────────────────────┘
```

能做的事：

| 操作 | 效果 |
|------|------|
| 📂 安装模组 | 选一个（或多个）.js 文件，自动放进 Mods 文件夹并登记，点「刷新游戏」生效（仅客户端；网页上没有这个按钮） |
| 关闭 / 启用 | 只是不加载，文件还在；记在本机（换服务器也认得） |
| 删除 | 文件从 Mods 文件夹里删掉（内置模组删不掉文件，就从加载列表里移除，可用「恢复内置模组」找回来） |
| 🌐 从服务器同步 | 把服务器上有、本机没有的模组全部下载安装 |

**模组存在哪（自动选择，不用管）**：

| 场景 | 存储位置 | 能做什么 |
|------|----------|----------|
| 手机 APK | App 私有目录 `files/mods/`（真·Mods 文件夹，选完文件自动进去并重载） | 装 / 启停 / 删，全都能 |
| 桌面客户端（exe）/ 双击 index.html | 浏览器本地模组库（IndexedDB），下次打开照常加载 | 装 / 启停 / 删，全都能 |
| 网页从服务器打开（/pc、/mobile） | 服务器自己的 `mode/模组/`，**网页玩家只读** | 只能"看 + 开关"（只影响自己这台设备） |

> 【batch226】为什么网页玩家不能装/删：网页打开时那个服务器是**别人的机器**，
> 随便让网页往服务器磁盘写文件既危险也说不清。模组由服务器主放进服务器的
> `mode/模组/`，所有人自动同步；玩家想用自己那套，就用手机 APK / 桌面客户端。

**联机自动同步**：只要连上过服务器，客户端就会自动对账（`/api/mods`），服务器有、本机没有的模组**自动下载安装**，弹一条提示，刷新后生效。也就是说：

> 把你的模组 .js 放进服务器的 `多文件版/mode/模组/`，所有连上来的玩家下次进游戏就都有它了，不用发文件。

模组作者要注意的：

- 模组**必须能在加载器里独立加载**（别依赖加载顺序之外的东西），因为同步来的模组会在内置模组**之后**执行；
- 想知道模组到底载入完了没有，看 `ModLoader.已载入 === true`（batch225 起有这个标记）；
- 服务端那三条接口有白名单：文件名只能是中文/字母/数字 + `.js`，单个不超过 512KB，`载入清单.js` 不许改。

## 3. 五分钟上手

打开 `多文件版/mode/模组/角色_夜莺.js`，从头读到尾，然后把名字、颜色、数值改成你自己的，就是一个新英雄。

最小骨架（能跑）：

```js
/* 模组：角色「我的英雄」—— 一句话说明他是干嘛的 */
(function () {
  'use strict';
  if (window.__myHeroModLoaded) return;          // 防止重复加载
  window.__myHeroModLoaded = true;
  if (typeof window.ModLoader === 'undefined') return;
  if (typeof window.HEROES === 'undefined') return;

  var 我的英雄 = {
    k: 'myhero',                     // 必填：字符串标识
    name: '我的英雄', tag: '输出', fac: '暗月',
    icon: '🗡️', color: 0xff6688, css: '#ff6688',
    passive: '我的被动：一句话说清楚。',
    skills: [
      { k: 'my_skill1', name: '技能一', icon: '💥', cd: 10, dur: 0, desc: '干什么用的' },
      { k: 'my_skill2', name: '技能二', icon: '🌀', cd: 16, dur: 3, desc: '干什么用的' },
      { k: 'my_skill3', name: '大招',   icon: '🌠', cd: 60, dur: 5, desc: '干什么用的' }
    ]
  };
  ModLoader.addHero(我的英雄);

  // 技能实现：返回 false 才会退回游戏原版分支；返回 true = "这个技能我处理了"
  ModLoader.addSkill('my_skill1', function (i, s, H) {
    showMsg('释放了技能一！', '#ff6688');
    return true;
  });

  // 每帧推进 + 包各种引擎函数（详见第 14 章）
  ModLoader.onApply(function () {
    if (typeof window.updateHero === 'function') {
      var _uh = window.updateHero;
      window.updateHero = function () { try { /* 我的每帧逻辑 */ } catch (e) { } return _uh(); };
    }
  });
})();
```

然后在 `载入清单.js` 里加上 `'角色_我的英雄'`，刷新页面，进选人界面就能看到。

## 4. ModLoader 接口总览

| 分类 | 接口 | 干什么用 |
|------|------|----------|
| 基础 | `register(obj)` / `onApply(fn)` / `refresh()` | 登记模组 / 全部载入后执行 / 刷新选人选图界面 |
| 英雄 | `addHero(hero)` | 加一个英雄 |
| 技能 | `addSkill(k, fn)` | 加一个自定义技能 |
| 武器 | `addWeapon(def)` / `setWeaponStats(slot,def)` / `selectWeapon(idx)` / `listWeapons()` | 加枪 / 改内置枪数值 / 切枪 |
| 地图 | `addMap(map)` / `addSpawn(id, pts, replace)` / `addSpikeMap(id)` | 加图 / 配出生点 / 声明支持爆能器 |
| 敌人 | `addEnemyType(key, def)` / `spawnEnemy(type,x,z)` | 加敌人类型 / 立刻刷一个 |
| 美术 | `addModel(name,fn)` / `getModel(name)` / `addScenery(obj)` / `removeScenery(obj)` / `addLight(l)` / `setEnv(o)` / `applyArt()` | 加模型 / 装饰物 / 灯 / 改天空雾灯 |
| 物理 | `setPhysics(o)` / `addPhysicsTick(fn)` / `removePhysicsTick(fn)` | 改重力等 / 每帧物理回调 |
| 剧情 | `addStory(chap)` | 加一个剧情章节 |
| 玩法 | `addGameMode(m)` / `setGameMode(id)` / `listGameModes()` / `addMPMode(m)` / `setTeams(n)` / `joinMP(mode,room)` | 自定义玩法 / 多人玩法 |
| 多人 | `heroBroadcast(k, data)` / `onRemoteHero(e, idx)` | 广播技能事件 / 自定义远端外观 |
| 清场 | `onFieldClear(fn)` / `clearField()` | 退出对局时清掉自己的场上物体 |
| 自检 | `spawnFree(x,z)` | 某点是否空地（控制台敲 `ModLoader.spawnFree(0,15)`） |

## 5. 英雄（addHero）

```js
ModLoader.addHero({
  k: 'nightingale',            // 必填。字符串标识，别和别的英雄重复
  name: '夜莺',
  tag: '医者',                  // 定位标签：输出 / 突进 / 医者 / 控场…
  fac: '暗月',                  // 阵营：正规军 / 暗月 / 未来 …（'' = 无阵营）
  facDesc: '暗月战线 · 歌声医师',
  icon: '🎵',                   // 选人界面上的图标
  color: 0x9ff0d0,              // 3D 特效主色（十六进制数字）
  css: '#9ff0d0',               // 界面文字颜色（CSS 字符串）
  passive: '余音绕梁：歌声持续期间，自身移速 +12%。',
  skills: [
    { k:'song_heal', name:'治愈之歌', icon:'🎶', cd:20, dur:6, desc:'7 米内每 0.5 秒回 6 点' },
    { k:'song_calm', name:'安神谣',   icon:'🕊️', cd:12, dur:0, desc:'12 米内瞬回 25 并解减速' },
    { k:'song_lullaby', name:'安魂曲', icon:'🌙', cd:75, dur:8, desc:'大招：15 米每秒回 10' }
  ],

  // —— 以下都是"联机才需要"的可选字段 ——
  sync: function (skillKey, data, src) { /* 别人放你的技能时，在他机器上复现 */ },
  remoteModel: function (model, info) { /* 自定义别人看你的第三人称外观 */ }
});
```

**字段说明**

| 字段 | 必填 | 说明 |
|------|------|------|
| `k` | ✅ | 字符串标识 |
| `name` / `tag` / `fac` / `icon` / `color` / `css` | ✅ | 界面显示 |
| `passive` | 建议 | 被动描述（真正生效要靠 `heroSpeedMul` 等钩子，见第 14 章） |
| `skills` | ✅ | 三个技能，`cd` 是冷却秒数，`dur` 是持续秒数（瞬发填 0） |
| `desc` | 建议 | 选人界面显示的技能说明，写清楚数值 |

**英雄下标怎么排**：0~3 正规军四位、4 蚀日者、5 闪电、6 影月、**7+ 是模组英雄**（按加载顺序往后排）。服务端对 7 以上一律放行，所以**加英雄不用改服务端**。

**被动怎么实现**：引擎在算移速时会调 `heroSpeedMul()`，包一层即可：

```js
ModLoader.onApply(function () {
  if (typeof window.heroSpeedMul === 'function') {
    var _hs = window.heroSpeedMul;
    window.heroSpeedMul = function () {
      var m = _hs();
      try { if (typeof SK !== 'undefined' && SK && SK.idx === 我的下标 && 我的 buff 还在) m *= 1.12; } catch (e) { }
      return m;
    };
  }
});
```

## 6. 技能（addSkill）

```js
ModLoader.addSkill('my_skill1', function (i, s, H) {
  // i = 技能序号(0/1/2)，s = 技能 def（含 cd/dur/name…），H = 当前英雄 def
  // 返回 false → 退回游戏原版分支；返回其它任何值 = "我处理完了"
  return true;
});
```

要点：
- **`k` 别和原版撞车**（原版有 dash / shield / eye / boom / portal / trap / ball / mine / flash / smash / fortify / rush / adren / aura / reflect 等）；
- 冷却由引擎管（`SK.cds`），你不用自己倒计时；
- 想支持"再按一次提前取消"，就包 `window.heroCast`（见第 14 章）；
- **联机时必须自己广播**（见第 11 章），否则只有你自己看得到。

**常用引擎函数**（都在全局，调用前建议 `typeof xxx === 'function'` 判一下 + try/catch）：

```js
showMsg('提示文字', '#9ff0d0');                    // 屏幕中间飘一句
spawnParticle(new THREE.Vector3(x, y, z), 0x9ff0d0, 12);   // 一撮粒子
heroFxRingAt(x, z, 0x9ff0d0, 0.3, 6, 0.6, y);      // 地面扩散环（r0→r1，life 秒）
heroFXZapAt(x, y, z);                              // 一道电弧
heroFxRingAt(x, z, color, r0, r1, life, y, nx, ny, nz);    // 带法线的贴面环
```

## 7. 武器（addWeapon / setWeaponStats）

### 6.1 新增一把枪

```js
var idx = ModLoader.addWeapon({
  name: '霰弹枪',
  melee: false,          // false=枪械（有弹药），true=近战
  damage: 0.45,          // 伤害倍率（1 = 原版步枪）
  magSize: 6,            // 弹匣容量
  fireRate: 750,         // 射速（毫秒/发）
  reloadTime: 2600,      // 换弹毫秒
  recoilMul: 1.4,        // 后坐倍率
  range: 45,             // 射程（米）
  pellets: 8,            // 每次发射的弹丸数（散弹 >1）
  spread: 0.022,         // 基础散布
  auto: false,           // false=半自动（要一下一下点），true=全自动
  magType: 'shotgun',    // 弹匣外形：rifle/shotgun/smg/sniper/lmg
  magPos: MAG_POS,       // 弹匣挂点（用引擎的 MAG_POS 即可）
  build: function (g) { /* 在 g（一个 Group）上搭第一人称模型 */ }
});
ModLoader.selectWeapon(idx);   // 立刻切过去
```

**和原版步枪"行为完全一致"的约定**：新枪和内置步枪一样能开镜、能换弹；射速/后坐/射程/弹丸/散布全部沿用步枪那套，区别只在三样——`damage`、`magSize`、`build()`。上面列的其它字段（fireRate/reloadTime/…）是**可选覆盖**，不写就用步枪的值。

### 6.2 第三人称：别人眼里的你的枪

**从 batch216 起，`build(g)` 不再只用于第一人称 —— 联机时每个远端玩家都会用同一个 `build` 复制一份枪模型挂到他手上。**
也就是说：你写的模型既要经得起"贴脸看"（第一人称），也要经得起"从侧面看"（第三人称）。

**硬性约定（不遵守会出现"别人那里枪飞出去 / 卡在身体里 / 只剩一把方块枪"）：**

| 约定 | 说明 |
|---|---|
| 只能往**传进来的 `g`** 里 `add` | 绝对不能 `weaponGroup.add(...)` 或 `camera.add(...)` —— 远端玩家没有你的 `weaponGroup`，那样建出来的东西会跑到你自己脸上 |
| 坐标单位是**米**、真人比例 | 不要为了让第一人称"看得清"把枪放大 1.5 倍，那样第三人称就是一把巨枪 |
| 组原点 ≈ **握把**，`-Z` 朝枪口，`+Z` 朝枪托 | 引擎按这个把"右手虎口"对到原点 |
| 不要引用第一人称专有全局 | `weaponGroup` / `currentMagMesh` / `leftHandAnchor` / `camera` 在远端玩家那边不是你想象的东西。要拿"当前弹药"之类的状态，用 `S.ammo`，别读弹匣网格 |
| 材质尽量复用 | 引擎会按材质把同材质的件合批（同材质 **≥2 件**就并成一个）。一把枪 200+ 件也能压到 30 次绘制；每件都 `new Material` 就没法合，帧率会掉 |
| 槽位号不要用负数 | `-1` 是纪念枪「长明」的保留槽位 |

**可选：完全自定义第三人称外观**

```js
var idx = ModLoader.addWeapon({
  name: '霰弹枪',
  build: function (g) { /* 第一人称 + 第三人称共用 */ },
  /* 想让第三人称长得不一样（比如远看更简化的 LOD），再给一个 tpBuild： */
  tpBuild: function (rig) { /* rig 是挂在右手上的 Group，原点≈握把，-Z 朝枪口 */ }
});
```

优先级：`def.tpBuild` > `def.build`（自动复制）> 引擎兜底的方块枪。

**弹匣与枪口**

- 第三人称的弹匣位置取自 `magPos`（和你给第一人称的挂点同一个）。不写就用默认挂点，换弹时弹匣会从那个位置掉下去。
- 引擎会自动登记枪口位置，别人开火时枪口火光和曳光从**枪口**出，不是从胸口出。如果你的枪口离原点特别远（长枪管），建议在 `tpBuild` 里把 `rig.userData.tpMuzzle` 设成正确坐标。

**和切枪有关的限制（batch218b 收紧过）**

手里拿着投掷物（手雷/闪光弹等）时**完全不能换武器**，三个入口全都拦：

| 入口 | 表现 |
|---|---|
| `switchWeapon(slot)`（数字键 / 滚轮 / 模组调用） | 直接 return，什么都不做 |
| `setCurrentGun(idx)`（B 菜单点枪卡 / 模组换枪） | 直接 return + 提示「先放下手里的投掷物」 |
| `setCurrentKnife(id)`（B 菜单点刀卡） | 直接 return |
| `showWeaponSelect()`（按 B） | 根本不弹菜单，只飘一句提示 |

**为什么拦得这么死**：`setCurrentGun` 会直接 `curGun=…; rebuildWeaponModel()`，绕过 `switchWeapon` 的守卫 ——
第一版只拦了 `switchWeapon`，结果按 B 点卡片照样能换，换完枪模型盖住了手里的投掷物、右下角名字也被重建的枪名顶掉。

**给模组作者的两条**：
1. 要换枪一律走上面这四个函数，**不要直接写 `curGun = …` 或 `currentWeapon = …`**，否则守卫拦不到你。
2. 如果你的模组自己维护"HUD 上的武器名"，记得 `SK.hold` 非空时让位——引擎在 `rebuildWeaponModel` 末尾会检查
   `SK.hold.名称` 并把右下角还原成手里那件东西的名字。


### 6.2.1 刀（addKnife）同样是这套规则

刀和枪走**同一套第三人称逻辑**，只是没有弹匣：

| 写法 | 第三人称表现 |
|---|---|
| `tpBuild(rig)` | 用你给的模型（**优先级最高**，爪刀就是这样，模型完全由模组控制） |
| 只有 `build(g)` | 引擎自动**复制第一人称那把刀**过来（和枪一样） |
| 两个都没写 | 内置方块刀兜底 |

⚠️ 两个坑：
1. 第一人称的刀模型**自带手**（`buildKnifeMeshes` 末尾会 `buildRightHand` 建手套 + 小臂）。
   引擎复制时会按材质（`gloveMat` / `skinMat`）把手剔掉，否则第三人称原有的手 + 复制来的手会叠在一起。
   **你自己的 `build` 里如果也建了手，同样会被剔掉** —— 别把"必须保留的部件"做成这两种材质。
2. 刀的原点在**护手**，复制后引擎会整体往前挪 7cm，让手握住刀柄而不是握着护手。

### 6.2.2 投掷物（addThrowable）

英雄技能"掏出一件东西拿在手上"用的道具。内置 14 种（手雷 / 闪光 / 烟 / 急救箱 / …）之外，
模组英雄可以注册自己的，**注册后第一人称和第三人称都会自动用它**：

```js
var code = ModLoader.addThrowable({
  id: 'shock',            // 必须和你在技能里写的 SK.hold.kind 一致
  name: '震荡雷',
  scale: 0.55,            // 可选，默认 0.55
  spin: 2.2,              // 可选：拿在手上时别人看到的自转速度（弧度/秒）
  mesh: function () {     // 每次都要**新建**一个，不要返回单例
    var g = new THREE.Group();
    /* …在这里搭模型，原点在物体中心、直径约 0.2 米… */
    return g;
  }
});
```

注册后引擎会自动：
- 把编号登记进 `NADE_CODE` / `NADE_KIND`（联机时别人知道你手上拿的是什么）
- **别人手上也会慢慢自转**（`spin` 字段控制转速，不写按 1.8 弧度/秒）
- 第一人称掏出它 → 用你的 `mesh()`
- 第三人称（别人看你）→ 用同一个 `mesh()`，并按真手雷比例缩放
- 摆位自动套用"破片手雷"的握持姿势

**扔出去之后的飞行也是兼容的**（`ModLoader.throwFx`）：

```js
// 出手那一瞬间调一次：编号 + 出生点 + 初速（米/秒）+ 生存秒数
ModLoader.throwFx(code, 出手点x, 出手点y, 出手点z, vx, vy, vz, 1.6);
```

别人屏幕上就会出现**同一个模型**沿抛物线飞过去 —— 落地会弹两下、旋转着飞、到点自动消失。
引擎负责的只有视觉：**伤害和落点结算仍然是你自己的事**（该发 `boom` 还是发什么，按你原来的写法来）。

`throwFx` 在单人模式下直接返回 false（不需要广播），不用担心调用时机。


### 6.3 开镜与散射相关字段

| 字段 | 作用 |
|------|------|
| `type: 'shotgun'` | 声明这是散弹枪 → 开镜默认保留 35% 散射 |
| `adsSpreadKeep: 0.35` | 开镜保留多少散射（0 = 完全无散射）。**优先级高于 type** |
| `adsFov: 18` | 开镜时的 FOV（越小放大越大；默认 45）。狙击枪用 18 ≈ 4 倍 |
| `scope: true` | 狙击镜：开镜显示镜框暗角 + 准星，并隐藏枪身手部 |
| `redDot: true` | 红点镜：开镜时隐藏实体镜身，屏幕中心显示红点准星 |
| `spreadReticle: true` | 散布圆准星：准星就是一个圈，圈多大散射就多大（散弹枪专用） |

## 8. 地图与出生点（addMap / addSpawn / addSpikeMap）

```js
ModLoader.addMap({
  id: 'volcano',                 // 必填，唯一
  name: '火山据点',
  desc: '选图界面显示的文字',
  ladder: false, tower: false,   // 有梯子/哨塔才写 true
  limit: 60,                     // 地图边界半径（米）
  spawns: [[0,20],[10,15],[-8,18]],   // 出生点表（也可以只用 addSpawn）
  build: function () {
    // 在这里往场景里放东西。**不要自己 scene.add**：
    // 引擎会先把 _mapTarget 指到你这张图的 Group，你只要往"当前目标"加：
    addBox(0, 0, 0, 10, 4, 10);       // 用引擎提供的建模 helper（见现有 buildMap* 函数）
  }
});
// 出生点也可以单独补（会顺手注册进 MAP_SPAWNS）：
ModLoader.addSpawn('volcano', [[0,20],[10,15]]);
// 想让这张图能玩爆能器模式，必须**连点位一起声明**（见 7.1 节）：
ModLoader.addSpikeMap('volcano', {
  sites: [{ x: -20, z: 10 }, { x: 20, z: 10 }],   // 必填：下包点 A/B
  spike: { x: 0, z: 34 }                          // 必填：爆能器出生点
});
```

**为什么必须配出生点**：开局是从该图的出生点表里**随机抽一个**把玩家放过去。没注册的话会 fallback 到经典图的 `[0,15]`——在你的图里可能就是墙里、坑里，或者直接悬空摔出地图。

**联机注意**：出生点表**服务端也有一份**（`MAP_SPAWNS`），新图要同步加到 `服务器/服务端.js` 里，否则联机开局位置不对。

### 7.1 让地图支持爆能器模式：必须声明下包点与爆能器出生点 ★

只声明"我支持爆能器"是不够的 —— **必须把点位一起交出来**，否则注册会被拒绝：

```js
ModLoader.addSpikeMap('volcano', {
  sites: [                        // 必填：下包点（A/B，1~4 个，每个 {x,z}）
    { x: -20, z: 10 },
    { x:  20, z: 10 }
  ],
  spike: { x: 0, z: 34 },         // 必填：爆能器出生点（开局掉包处，{x,z}）
  atk: [0, 40], def: [0, -40],    // 可选：进攻方 / 防守方出生区（默认 [0,40] / [0,-40]）
  soloSpawn: [0, 40]              // 可选：单人训练出生点（默认取该图出生点表第一个）
});
```

**规则（重要）**

- `sites` 和 `spike` **缺任意一个 → 注册失败**：`addSpikeMap` 返回 `false`，控制台红字说明缺什么。
- 注册失败 = `spikeMapOk('volcano')` 仍是 `false` = **这张图不会出现在爆能器模式的选图里**。
  这是故意的：以前只声明 id 也能进，服务端 `SPIKE_MAP_CFG` 里没有这张图就会
  **静默套用经典图的坐标** —— 在你的图里可能正好是墙里 / 坑里 / 图外，比直接不出现更难排查。
- 返回值可以直接判断：`if (!ModLoader.addSpikeMap('volcano', cfg)) console.warn('点位没写对');`

**怎么挑点位**

- 下包点要**离双方出生点都远一点**，并且是空地。控制台里敲 `ModLoader.spawnFree(x, z)` 验证：`true` = 空地。
- 两个下包点分居中线两侧，别挤在一起（否则守方一个站位就能看死两个点）。
- `spike`（爆能器出生点，也就是进攻方持包的出发点）放在进攻方一侧。

**联机**：点位是**客户端**加载的，服务端本来没有你的图。进房时会由**队长自动把 `sites/spike` 报给服务端**
（你不用写额外代码），所以**请确保队长也装了这个模组**，否则整房会退回经典图点位（服务端日志会有提示）。
内置的三张图（classic / eclipse / lab）服务端已有配置，不接受覆盖。

## 12. 联机适配（服务端要同步什么）

### 11.1 先理解架构

- **服务端是白名单**：不认识的 `m.t` 消息**直接丢弃**，没有兜底转发；
- **位置是各客户端权威**：每个人自己算自己的坐标，通过 `t:'p'` 上报，服务端只存 `p.x/p.z` 并转发；
- **伤害/治疗由服务端结算**：客户端发请求，服务端判合法后扣/回血并广播；
- **技能特效各客户端本地复现**：和内置英雄一致。

### 11.2 你的模组技能怎么让所有人看到、吃到

```js
ModLoader.addSkill('my_aoe', function (i, s, H) {
  // ① 本地：播特效 + 本地该干的事
  heroFxRingAt(camera.position.x, camera.position.z, 0xff6688, 0.3, 8, 0.7);

  // ② 联机：广播给同房其他人 → 他们会调用 我的英雄.sync('my_aoe', data, 那个玩家对象)
  ModLoader.heroBroadcast('my_aoe', { x: camera.position.x, z: camera.position.z, r: 8 });

  // ③ 伤害：**由释放者**走服务端权威结算（别让每个客户端各扣一遍）
  //     打真人：netSend({ t:'hit', i: 目标.netId, d: 伤害, h: 是否爆头 })
  return true;
});
```

在英雄 def 里写 `sync`，把特效在别人机器上再放一遍：

```js
sync: function (skillKey, data, src) {
  if (skillKey === 'my_aoe' && data) {
    heroFxRingAt(data.x, data.z, 0xff6688, 0.3, data.r, 0.7);
    spawnParticle(new THREE.Vector3(data.x, 1, data.z), 0xff6688, 14);
  }
}
```

### 11.3 想自定义远端外观

```js
remoteModel: function (model, info) {
  // model 同 _buildPlayerModel() 的返回（含 root / modelGroup / head…）
  try { model.root.traverse(function (o) { if (o.isMesh && o.material) o.material.color.setHex(0xff6688); }); } catch (e) { }
}
```
不写就用通用联机模型（所有人长得一样）。

### 11.4 需要新的服务端能力时（比如"持续治疗"、"引力吸人"）

引擎已经提供的服务端消息：

| 消息 | 作用 | 谁发 |
|------|------|------|
| `{t:'hit', i, d, h}` | 对某个玩家造成伤害（服务端校验） | 释放者 |
| `{t:'heal', x, z, r, a, us}` | 范围治疗（满血不治、倒地扶起）；`us=1` 顺带解减速 | 施法者（每跳发一次） |
| `{t:'grav', x, z, r, f}` | 范围引力：被服务端通知的客户端把自己往中心拉 | 施法者（每 ~70ms 一次） |
| `{t:'modsk', k, d}` | 自定义技能事件，服务端原样转发同房他人 | `heroBroadcast` 自动发 |
| `{t:'hero', h}` | 我换了英雄 | 引擎在选英雄时自动发 |
| `{t:'unslow'}` | 解除减速 | 服务端发 |

如果这些还不够，就要**改服务端**：
1. 改权威源 `服务器/服务端.js`，在 WS 消息分发链里加一个 `else if (m.t === '你的消息')` 分支；
2. 重跑 `工具/生成多文件服务端.py`（会同步到 `多文件版/服务端.js`）；
3. 客户端用 `netSend({t:'你的消息', ...})` 发。

**铁律：改服务端必须改权威源再重跑生成脚本**，只改 `多文件版/服务端.js` 会在下次重建时被覆盖。

### 11.5 联机自测

改完联机相关代码，先用 Node 双客户端验服务端转发，再用 Edge 无头验客户端路由，最后才让人上线测。项目里 `服务器/自测_*.js` 有几套现成自测可以照抄。

## 15. 每帧钩子与退出清场

### 14.1 包引擎函数（onApply）

引擎函数都是全局函数，`onApply` 里包一层最稳妥（此时所有游戏函数都已就位）：

```js
ModLoader.onApply(function () {
  // 每帧推进
  if (typeof window.updateHero === 'function') {
    var _uh = window.updateHero;
    window.updateHero = function () { try { 我的每帧逻辑(); } catch (e) { } return _uh(); };
  }
  // 提前取消（再按一次技能键 = 收起）
  if (typeof window.heroCast === 'function') {
    var _hc = window.heroCast;
    window.heroCast = function (i) {
      i = i | 0;
      try { if (i === 0 && 我的状态还在) { 收起(); return true; } } catch (e) { }
      return _hc.apply(this, arguments);
    };
  }
  // 被动
  if (typeof window.heroSpeedMul === 'function') { /* 见第 4 章 */ }
  // 死亡 / 结算时清理
  if (typeof window.gameOver === 'function') {
    var _go = window.gameOver;
    window.gameOver = function () { 清理(); return _go.apply(this, arguments); };
  }
});
```

> ⚠️ **不要跨文件引用另一个分片里的函数**（客户端是 23 个分片，玩家浏览器可能缓存旧分片 → `ReferenceError`）。核心路径用到的辅助函数，请在你自己的模组文件里就地定义，并 try/catch 兜底。

### 14.2 退出对局清场（onFieldClear）★ 一定要写

退出对局（回主菜单）时引擎会调 `ModLoader.clearField()`，逐个执行这里登记的函数。**你加进场景的物体如果不在这里收掉，回主菜单再开一局时还会留在场上**（上一局的子弹、光环、召唤物…）。

```js
ModLoader.onFieldClear(function () {
  try { 移除我的场上物体(); } catch (e) { }
});
```

引擎自己会清：AI 敌人、玩家子弹、敌人子弹、拾取物、粒子、烟团、投掷物、英雄技能区域（电区/黑日/陷阱/闪电球/传送门/暗影毒圈）、屏幕特效。

## 17. 完整范例：夜莺（治疗英雄）逐行剖析

文件：`多文件版/mode/模组/角色_夜莺.js`。它是"能联机的治疗英雄"最完整的样板，重点看这五处：

**① 英雄 def + sync**——治疗数值走服务端，视觉走 sync：
```js
sync: function (skillKey, data, src) {
  if (!data) return;
  if (skillKey === 'song_heal' || skillKey === 'song_lullaby') spawnRemoteRing(data, src);
  else if (skillKey === 'song_calm') remoteCalmFx(data);
}
```

**② 治疗一跳：联机只发包，单机本地回血**（避免双重治疗）：
```js
function healTick() {
  if (netOn()) {
    netSend({ t: 'heal', x: camera.position.x, z: camera.position.z, r: ST.r, a: ST.amt });
  } else {
    if (S.hp > 0 && S.hp < S.maxHp) { S.hp = Math.min(S.maxHp, S.hp + ST.amt); updateHp(); }
  }
}
```
> 服务端 `t:'heal'` 会给同房范围内所有人回血（包括你自己，靠 `t:'hp'` 广播回来），所以联机时本地**不要**再回一次。

**③ 光环模型**：`RingGeometry`×2 + `CircleGeometry`，每帧跟着玩家、按半径缩放：
```js
g.position.set(camera.position.x, gy + 0.06, camera.position.z);
g.scale.set(ST.r, ST.r, 1);
```

**④ 每帧推进**：包 `window.updateHero`，歌声倒计时 + 每 `every` 秒治疗一跳 + 音符粒子。

**⑤ 退出清场**：
```js
ModLoader.onFieldClear(function () {
  try { if (ST.song > 0) endSong(true); } catch (e) { }
  try { removeRing(); } catch (e) { }

```

## 18. 常见坑与铁律

1. **改引擎要改权威源再重建**：客户端 `网页3D枪战游戏.html` → `工具/拆分.py`；服务端 `服务器/服务端.js` → `工具/生成多文件服务端.py`。只改 `多文件版/` 里的生成物，下次重建就被覆盖。
2. **模组文件是活源**：`多文件版/mode/模组/*.js` 是手维护的，重建不会覆盖，改完刷新页面即可。
3. **别跨分片引用函数**：客户端拆成 23 个分片，引用别的分片的函数，玩家缓存旧分片时就 `ReferenceError`，而且只在玩家机器上复现。辅助函数就地定义 + try/catch。
4. **服务端是白名单**：新消息类型不加分支就被丢弃。
5. **持续区域用 `mapOf()` 判同房，别用 `normMapId()`**：爆能器模式下房间钥匙是 `模式:房号`，和地图 id 永远不等，用错会让范围技能完全失效。
6. **联机伤害必须服务端权威**：让每个客户端各扣一遍会重复扣血；让释放者发一次请求最稳。
7. **`HEROES` 下标 7+ 服务端放行**，但**越界/乱填会被打回天狼**；解锁类英雄（蚀日者/闪电）有服务端校验，改客户端数据没用。
8. **新图必须配出生点**（客户端 + 服务端两份），否则出生点 fallback 到经典图。
9. **写中文**：文件名、界面文字、`showMsg` 提示、代码注释，全部中文。
10. **测试**：语法 `node --check 你的模组.js`；逻辑用 Edge 无头实测；联机用 Node 双客户端验转发。测血量类逻辑时，记得先清掉 `enemies`（防守模式的小兵会打玩家，数据全是脏的）。

## 19. 自定义资产：闪光特效 / 背景 / 主菜单音乐【batch228】

不需要写代码 —— 把文件丢进 `mode/模组/` 就行（玩家自己加，不属于基础游戏）：
